# CLAUDE.md (frontend)

React 19 + Vite + TypeScript SPA with shadcn/ui (Base UI flavour, preset `b2BnwC9Oi`, style `base-vega`), urql and React Router. It uses Node, not Maven: **npm/npx only, never bun.** The API is GraphQL only (see the root `CLAUDE.md` for the backend schema and error codes).

```bash
npm run dev        # http://localhost:5173; proxies /graphql to :8080 (same origin, so the SESSION cookie needs no CORS)
npm run codegen    # regenerate src/gql from ../src/main/resources/schema/*.graphqls; commit the result
npm run typecheck  # tsc -b (not --noEmit: the root tsconfig only has references)
npm run lint && npm test && npm run build
```

Do not start Docker or the backend stack without asking the user.

## Layout

- `src/features/<feature>/`: pages, hooks and `graphql(...)` documents of one feature (`auth`, `tenants`).
- `src/components/`: app components (`app-sidebar`, `nav-user`, `company-switcher`). `src/components/ui/` is shadcn-generated: add with the CLI, do not hand-write.
- `src/routes/`: layouts and top-level pages. `src/lib/`: urql client (`graphql.ts`), error helpers (`errors.ts`), selected company (`tenant.ts`).
- `src/gql/` is generated by codegen and committed. Never edit it by hand. The Docker build also runs `codegen` against the backend schema files.

## GraphQL

- Write operations as `graphql(`...`)` documents next to the feature that uses them, then run `npm run codegen` (also after any backend schema change). Use the generated types (`CreateTenantInput`, ...) instead of hand-written ones.
- The API answers HTTP 200 and reports failures in `errors[].extensions.code`. Use `errorMessage(error)` / `errorCode(error)` from `lib/errors.ts` and show the message with `FormError`.
- urql's cache did not refresh `myTenants` after a mutation, so `useCompanies().refresh()` is awaited after every company mutation. Do the same for new lists that mutations change.

## Forms

`react-hook-form` + `zod` via `zodResolver`, with shadcn `Controller` + `Field` / `FieldError`. Type form values with the generated input type and assert the schema with `nameSchema satisfies z.ZodType<CreateTenantInput>`, so it fails to compile if the API changes (see `features/tenants/company-form-page.tsx`).

## Auth and tenants

- The session cookie is the source of truth: `SessionProvider` reads `me`, and tokens are never stored. `RequireAuth` / `PublicOnly` guard routes. There is no frontend authorization yet.
- Emailed codes are case-sensitive, six-character alphanumeric strings: send exactly what the user typed.
- The selected company is the `X-Tenant-Id` header, kept in `lib/tenant.ts` (localStorage) and sent by the urql client. `CompaniesProvider` (in `DashboardLayout`) loads `myTenants` and exposes `useCompanies()`. A mutation that must act on another company (edit, inactivate, reactivate) passes `tenantContext(id)` as the operation context.
- Tenants are never deleted: the UI offers Inactivate / Reactivate. The UI says "Company", the API says `Tenant`.

## UI (shadcn)

- Follow the shadcn skills in `.agents/skills` (`shadcn`, `migrate-radix-to-base`). This is the Base UI flavour: triggers use `render={<... />}`, not `asChild`.
- Layouts are not invented. Start from a shadcn block and change as little as possible (`sidebar-07` for the sidebar and company switcher, `login-01` for auth forms). If no block fits, say so and list the candidates before composing from shadcn components.
- Use components, not custom markup: `Empty`, `Skeleton`, `Badge`, `Alert`, `AlertDialog`, `InputGroup`. Icons are `lucide-react`; icons inside components take no size classes.
- Add components with `npx shadcn@latest add @shadcn/<name>` (name the registry explicitly), then read the added files.
- Run prettier only on files you changed: it reformats `src/index.css`.

## Tests

Vitest + Testing Library (`npm test`). Mock `useCompanies` / `urql`'s `useMutation` with `vi.mock` for component tests (see `company-switcher.test.tsx`, `company-form-page.test.tsx`); guard tests pass a fake urql client (see `guards.test.tsx`).
